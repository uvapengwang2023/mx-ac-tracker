## 3. 工作簿结构

最终 Excel 必须包含以下 Sheet：

| Sheet | 用途 |
|---|---|
| `汇总_核心参数` | 一机型/容量一行，给网站录入和业务查看使用 |
| `扩展参数_图片PDF` | 保留图片/PDF 中更细的技术字段 |
| `型号映射` | 拆分蒸发器/冷凝器、单冷/冷暖型号 |
| `功能卖点` | 按系列整理卖点，保留来源 URL 和证据字段 |
| `来源与口径` | 记录每个来源、时间、用途和处理口径 |
| `异常检查` | 记录需复核项、来源限制和疑似源文件异常 |

不要只做一个平表。来源和异常如果不单独成表，后续录入人员很难判断哪些值可以直接用、哪些值只是按源图保留。

## 4. 字段标准化口径

核心参数字段应尽量稳定，不要因为某个来源没有字段就改列名。

核心字段包括：

| 字段 | 口径 |
|---|---|
| 品牌 | 固定为 `Prime` |
| 系列 | A1 Advanced / Bright 1 / R3 Advanced / Bright 3 / Vantage 3 / Ultra 3 |
| 型号/表头 | 来源表格中的型号；Bright 1 无型号代码时用容量描述 |
| 容量标识 | 12K / 18K / 24K / 36K 或图片中容量描述 |
| 容量_Ton | 12K=1，18K=1.5，24K=2，36K=3 |
| 制冷量_BTU/h | 图片有 BTU 时按图；PDF 只有 W 时按型号容量标识换成 12000/18000/24000 |
| 制热量_BTU/h | 同上；无制热字段则空 |
| 电源/电压 | 保留原文，例如 `208-230V~/60Hz/1P` |
| 规范电压_V | 115 或 220，用于筛选 |
| EEER/EER | 图片中的 `EEER`、PDF 中的 `REE` 或 `EER` 可统一放入该列，但来源说明中要保留原文名 |
| SEER/SEEER | 图片中的 `SEEER`、`SEER` 统一放入该列 |
| HSPF | 仅 Bright 3、Ultra 3 等来源提供时填写 |
| 冷媒类型_规范 | 统一为 R410A 或 R32 |
| 冷媒_原文 | 保留如 `R32/500g`、`R410a/2010g` |
| 冷媒充注_kg | g 转 kg；若源文件未给充注量则空 |
| 尺寸 | 以源图顺序原样保留为字符串，不强行拆成长宽高 |
| 来源 URL | 必填 |
| 网站录入年月_链接 | 必填；从 URL 提取 |
| 图片/PDF元数据时间 | 可填；只作审计 |
| 备注 | 说明来源限制、单位转换、异常保留 |

数值处理规则：

1. 西语小数逗号转小数点，例如 `18,25` 录入为 `18.25`。
2. 带范围的值保留为字符串，例如 `9.1(2.0-11)`。
3. 尺寸中的 `×` 和 `*` 不强制统一，尽量保留源文件写法。
4. R410a、R410A 统一规范为 `R410A`；R32 保持 `R32`。
5. 不要把 PDF 元数据时间写成网站录入年月。

## 5. 型号映射规则

Prime 的型号前缀有明显规律：

| 前缀 | 含义 |
|---|---|
| EMPRC | Evaporadora / 蒸发器 / Solo Frío |
| EMPRN | Evaporadora / 蒸发器 / Frío-Calor |
| CMPRC | Condensadora / 冷凝器 / Solo Frío |
| CMPRN | Condensadora / 冷凝器 / Frío-Calor |

处理原则：

1. 来源表中给出型号代码时，拆到 `型号映射` Sheet。
2. Bright 1 图片没有型号代码，不要凭容量推断 EMPR/CMPR 型号。
3. 如果表头型号和型号格不一致，应放入异常检查，而不是自动改正。

### 6.5 Vantage 3

来源：`FICHA_V3_compressed.pdf`  
记录：4 条：`121-V3`、`122-V3`、`182-V3`、`242-V3`。

功能页卖点：

- Super Silencioso。
- SEER 20。
- GoldShield 抗腐蚀涂层。
- Auto Limpieza。
- Gas Ecológico R32。
- WiFi Ready，WiFi 通信接口为可选。
- 防电压峰值保护。

技术表特点：

- 参数页标题为 `PRIME INVERTER VANTAGE 3 / ESPECIFICACIONES MODELOS Y CAPACIDADES`。
- 表中容量单位为 W，例如 12K 对应 `3520 (800-4100)`。
- 为了与网站录入和前批次统一，核心表中的制冷/制热量按容量标识记录为 BTU/h：12K=12000，18K=18000，24K=24000。
- W 原文保留在扩展表的 `制冷量原文`、`制热量原文`。

注意事项：

- 表格单位栏有 `KW`，但数值是 1040、1200、1400、2100 等 W 级数值，判断为源文件排版/单位显示问题；核心表按 W 录入。
- PDF 文本抽取顺序会打散，应结合渲染图核对列。
- 24K 净重显示 `13/28.66`、`31.5/69.45`，含 kg/lb 双单位；核心净重字段录入 kg 值 13 和 31.5。

## 7. PDF 处理经验

两个 PDF 都是 2 页：

- 第 1 页：功能卖点。
- 第 2 页：技术参数表。

推荐处理流程：

1. 先用 PDF 文本抽取获取候选文本。
2. 再把第 2 页渲染成图片核对表格列。
3. 文本抽取顺序打散时，以渲染图的视觉列为准。
4. 不要只信文本抽取结果，尤其是型号行、单位行、容量行。

本次生成过的渲染图目录：

`data/prime/source_pdfs_20260528_103702/thumbs/`

关键经验：

- Vantage 3 的表格在 PDF 文本中型号和参数顺序混杂，必须看渲染图。
- Ultra 3 的技术表整体更清晰，但底部只有冷凝器净尺寸，没有包装尺寸。
- PDF 元数据时间可保存，但不应作为网站录入年月。

## 8. 功能卖点整理口径

功能卖点表不应臆造宣传语，只能来自：

1. 图片标题。
2. PDF 功能页。
3. 参数表明确字段，例如 SEER、R32、WiFi、HSPF。

每条卖点必须保留：

- 产品/系列。
- 功能/卖点。
- 整理说明。
- 来源 URL。
- 网站录入年月。
- 证据字段。

本批次必须覆盖全部 6 个系列。如果某个系列在核心表中存在，但功能卖点表中不存在，应判定为漏项。

## 9. 异常检查规则

必须把以下类型写入 `异常检查` Sheet：

| 类型 | 例子 | 处理 |
|---|---|---|
| 源值疑似不合理 | A1 36K 适用面积 `15~23 m²` | 按源保留，提示复核 |
| 来源字段缺失 | Bright 1 无型号代码 | 不推断，字段留空 |
| 时间口径差异 | Bright 3 URL 2025-11，EXIF 2025-10 | 网站录入年月用 URL，EXIF 仅审计 |
| 单位不一致 | Vantage 3 表头 KW 但数值为 W 级 | 核心按 W，扩展保留原文 |
| 范围异常 | Ultra 121-U3 电流标称值大于范围上限 | 按源保留，提示复核 |
| 标签混合 | Ultra HSPF/系统行混合显示 | 归入 HSPF 并备注 |

建议后续规则化：

- 36K 适用面积小于 40 m²，提示复核。
- 电流标称值大于括号范围上限，提示复核。
- 来源 URL 有 `/uploads/YYYY/MM/` 但字段为空，提示错误。
- 核心表中的系列未出现在功能卖点表，提示漏项。
- 型号映射缺失但来源不是简版图，提示复核。

## 10. AI 与脚本分工

不需要 AI API 的环节：

- 下载 URL。
- 解析 `/uploads/YYYY/MM/`。
- 文件命名。
- CSV 行数统计。
- 生成 Excel。
- 检查 zip 完整性。
- 检查系列覆盖。
- 按规则做异常检测。

需要或建议 AI 的环节：

- 识别图片里的表格。
- 判断 PDF 表格列是否错位。
- 从 PDF 功能页提取卖点。
- 把西语卖点整理成中文说明。
- 判断疑似异常应如何备注。

交接原则：

低成本脚本先跑，AI 只处理视觉识别、语义归纳和异常解释。AI 的输出不能直接当最终事实，必须有来源 URL、截图/渲染图或原文证据。

## 11. 复现步骤

后续接手者应按以下顺序执行：

1. 新建时间戳，不覆盖旧目录。
2. 下载所有图片/PDF 到 `data/prime/source_*_<timestamp>/`。
3. 记录来源 URL、文件名、网站录入年月。
4. 对图片直接查看参数表，必要时裁剪放大。
5. 对 PDF 先抽文本，再渲染第 2 页核对表格。
6. 按字段字典录入核心参数。
7. 将完整字段放入扩展参数表。
8. 拆型号映射。
9. 提取功能卖点，确保覆盖全部系列。
10. 写来源与口径说明。
11. 写异常检查。
12. 导出 Excel 和 CSV。
13. 校验输出文件。
14. 最后向用户只交付新版文件，不覆盖历史版本。

## 13. 不要做的事

1. 不要覆盖旧文件。
2. 不要把 EXIF/PDF 元数据时间当成网站录入年月。
3. 不要给 Bright 1 虚构型号代码。
4. 不要把 PDF 文本抽取结果未经渲染图核对就入表。
5. 不要自动修正源文件疑似异常值，应按源保留并在异常检查中提示。
6. 不要把 W 和 BTU/h 混在同一个字段里不说明。核心表可统一为 BTU/h，扩展表必须保留 W 原文。
7. 不要因为字段缺失就删除整列。缺失字段留空，并在备注或异常检查说明。
8. 不要只做 CSV。业务交付需要 Excel 的多 Sheet 结构。

## 14. 后续改进建议

建议把本次经验沉淀为工具：

1. URL 时间解析脚本：自动提取 `/uploads/YYYY/MM/`。
2. 来源 manifest：保存 URL、本地文件、元数据、下载时间。
3. 空调字段 schema：固定核心字段和扩展字段。
4. 异常规则 YAML：自动检查面积、电流范围、字段缺失、系列覆盖。
5. PDF 渲染脚本：自动输出第 1 页功能页、第 2 页参数页图片。
6. 功能卖点提取模板：要求 AI 输出“卖点、说明、证据字段、来源 URL”。
7. Excel 构建脚本模板：固定 Sheet 和表格样式。

优先级最高的是：

1. 产品覆盖校验。
2. URL 网站录入年月提取。
3. 异常检查规则。
4. PDF 渲染核对。
5. 新文件命名与版本管理。
